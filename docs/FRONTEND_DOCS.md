# ESCA HSE — واجهة الويب

نظام إدارة السلامة والصحة المهنية لمصنع أكسسوارات الكابلات (Elsewedy Cables — ESCA).

هذا المستودع فيه **الجزء الخاص بـ Member 3 — واجهة الويب (React)** من مشروع التدريب الصيفي: إعادة بناء
الـ mockup الثابت كتطبيق SPA ديناميكي مربوط بالـ API الحقيقي بدل الأرقام المكتوبة يدوياً، مع الحفاظ على
تخطيط RTL والواجهة العربية.

---

## 1. التشغيل

```bash
cd web && npm install && npm run dev
```

التطبيق يفتح على <http://localhost:5180>.

الواجهة **بتشتغل لوحدها من غير أي backend** — فيه محوّل محاكاة محلي بيرد على نفس مسارات الـ API. ده
مقصود: الـ frontend مايستناش خدمات Spring Boot تخلص عشان يبدأ.

### الحسابات

كل الحسابات محمّلة من ورقة `Users` في ملف البيانات المرجعية (٢١ حساب)، بالإضافة لحساب إداري واحد.

**الحساب الأساسي:** `mostafa` / `mostafa2026` — صلاحية كاملة (HSE Manager).

**حسابات الملفات** — كلمة المرور بنمط ثابت: `esca@` + رقم المستخدم، يعني `user.008` كلمة مروره `esca@008`.

| المستخدم | كلمة المرور | الدور | النطاق |
|---|---|---|---|
| `user.001` – `user.007` | `esca@001` … `esca@007` | Department Manager | قسم واحد لكل حساب |
| `user.008` | `esca@008` | HSE Manager | الموقع بالكامل |
| `user.009` | `esca@009` | Occupational Doctor | العيادة |
| `user.010` – `user.012` | `esca@010` … `esca@012` | HSE Officer | المناطق المسنَدة |
| `user.013` – `user.016` | `esca@013` … `esca@016` | Shift Supervisor | الوردية |
| `user.017` – `user.018` | `esca@017` · `esca@018` | Maintenance Technician | الأعمال المسنَدة |
| `user.019` | `esca@019` | Contractor | **موقوف — لا يستطيع الدخول** |
| `user.020` | `esca@020` | Auditor | قراءة فقط |
| `svc.automation` | `esca@service` | Automation Service | حساب خدمة |

اسم المستخدم غير حسّاس لحالة الأحرف وبتتشال منه المسافات الزايدة.

> كلمات المرور دي **للنسخة التجريبية بس** — مولّدة من اسم المستخدم لأن الملفات مافيهاش عمود
> كلمات مرور (ولا المفروض يكون فيها). لما Spring Security يشتغل، المصادقة كلها بتنتقل للخادم
> والكلام ده بيختفي.

### الأدوار والصلاحيات

عشرة أدوار جايّة من ورقة `RBAC_Matrix`، وكل دور ليه درجة وصول لكل وحدة بنظام CRUD
(`CRUD` · `CRU` · `CR` · `R` · `NONE`) مع علمين صريحين: اعتماد المخاطر العالية، وتصدير التقارير.

ملف `web/src/permissions.js` بيقرأ المصفوفة دي ويحوّلها لتلات حاجات: الشاشات اللي تظهر في
القايمة، الشاشات اللي تفتح بالمسار المباشر، والأزرار اللي تشتغل. مصدر واحد، فمافيش احتمال
إن التلاتة يختلفوا.

| الدور | الشاشات | تسجيل بلاغ | اعتماد عالي المخاطر |
|---|---|---|---|
| HSE Manager | 18 | ✅ | ✅ |
| Auditor | 17 | ❌ | ❌ |
| HSE Officer | 14 | ✅ | ❌ |
| Department Manager | 14 | ✅ | ❌ |
| Shift Supervisor | 11 | ✅ | ❌ |
| Maintenance Technician | 11 | ✅ | ❌ |
| Worker / Contractor | 11 | ✅ | ❌ |
| Occupational Doctor | 10 | ✅ | ❌ |
| Automation Service | 17 | ❌ | ❌ |

الشاشات المحجوبة مش مخفية من القايمة وخلاص — المسار المباشر بيدي شاشة «مش ضمن صلاحياتك».
ومع ده **ده مش أمان**: كل قاعدة هنا لازم يكون ليها قاعدة مقابلة في Spring Security على الخادم.

## 2.5 تحميل بيانات المصنع

كل الأرقام في النظام محمّلة من أربع ملفات Excel وفّرها المصنع — مافيش رقم واحد مكتوب بالإيد.

```bash
python etl/build_seed.py
```

السكربت بيقرا الملفات الأربعة، بيكتشف صف العناوين الحقيقي (كل ورقة فوقها بانر وسطر وصف
وسطر فاضي)، وبيكتب `web/src/api/mock/seed.generated.js` — نسخة مطابقة للأوراق بنفس أسماء
الأعمدة ونفس الأكواد.

| البند | العدد |
|---|---|
| الملفات | 4 |
| الجداول المحمّلة | 59 |
| السجلات | 844 |

الملف المولَّد **ماينفعش يتعدّل بالإيد** — أول ما تيجي نسخة جديدة من الأوراق، شغّل الأمر تاني.
ملف `web/src/api/mock/data.js` هو الوصلة اللي بتحوّل الأعمدة الخام لشكل الشاشات، وملف
`web/src/labels.js` فيه الترجمة العربية للأكواد (`HOT_WORK` ← عمل ساخن). النصوص الحرة اللي
في الأوراق (عناوين الحوادث، وصف المخاطر) بتتعرض زي ما هي — ترجمتها معناها اختراع محتوى
مش موجود في المصدر.

## 3. عقد الـ API

كل نداء بتعمله الواجهة معرّف في ملف واحد: **`web/src/api/endpoints.js`**.

ده نص العقد من ناحية الـ frontend — أي مسار موجود في الملف ده ومش موجود في Swagger معناه فجوة تكامل
لازم تتحل. والعكس صحيح: لو غيّرتوا شكل أي response، الملف ده هو المكان الوحيد اللي محتاج يتعدّل.

أمثلة على الشكل المتوقع لكل response موجودة في `web/src/api/mock/data.js` — المحاكاة مبنية على نفس
الـ payload اللي الواجهة مستنياه، فاعتبروها المرجع.

**المسارات المطلوبة حسب المالك:**

- **Member 1** — `/incidents`, `/incidents/{id}`, `/incidents/stats`, `/incidents/{id}/rca`, `/capa`,
  `/permits`, `/permits/{id}/approvals`, `/permits/{id}/approve`, `/permits/simops`, `/permits/checklist`,
  `/risk/hazards`, `/risk/distribution`, `/jsa`, `/auth/login`, `/auth/me`, `/audit-log`
- **Member 2** — `/departments`, `/inspections/*`, `/training/*`, `/hazmat/*`, `/occupational-health/*`,
  `/reports/*`, `/integrations`, `/dashboard/*`
- **Member 6** — `/fire-equipment`, `/fire-equipment/attention`, `/fire-equipment/coverage`, `/ppe/*`
- **AI Students** — `/iot/sensors`, `/iot/events`, `/ai/detections`, `/ai/models`, و`POST /ask` على خدمة الوكيل

## 4. الشاشات

18 شاشة + شاشة دخول، كلها RTL:

| الشاشة | المسار | الملاحظات |
|---|---|---|
| لوحة القيادة | `/` | تجميع من كل الخدمات · KPIs · اتجاه شهري · هرم Heinrich |
| البيانات المرجعية | `/master-data` | تغطية البيانات المحمّلة من ملفات المصنع + عدد العاملين لكل قسم |
| الأقسام والمناطق | `/departments` | 9 أقسام و14 منطقة من ملف البيانات المرجعية |
| الحوادث والبلاغات | `/incidents` | سجل + بحث وفلترة + نموذج تسجيل + سجل تحليل السبب الجذري |
| معدات الحريق | `/fire-equipment` | خريطة طفايات · قائمة الإجراء الفوري · تغطية المناطق |
| معدات الوقاية | `/ppe` | مخزون + معدات ثابتة + مصفوفة PPE حسب المنطقة |
| التفتيش والجولات | `/inspections` | جدول + ملاحظات + بانى النماذج |
| تقييم المخاطر | `/risk` | مصفوفة 5×5 تفاعلية — الضغط على أي خانة يفلتر السجل عليها |
| تصاريح العمل | `/permits` | لوحة تصاريح بأعمدة الحالة · سير الاعتماد والتوقيع · قواعد SIMOPS |
| JSA | `/jsa` | سجل التحليلات + تفصيل خطوة/خطر/ضابط |
| المواد الخطرة | `/hazmat` | سجل كيماويات + مصفوفة توافق التخزين |
| الصحة المهنية | `/occupational-health` | خطة الفحوص + قياسات التعرض |
| التدريب والتأهيل | `/training` | مصفوفة الكفاءات + الشهادات المنتهية |
| المراقبة الآلية | `/ai-iot` | قراءات حساسات حية (polling) + سجل تنبيهات + كشف بصري |
| الربط والتكامل | `/integrations` | قنوات الاستيراد وحدود النطاق |
| الأمن والتدقيق | `/security` | مصفوفة الصلاحيات + سجل تدقيق قابل للبحث |
| معمارية النظام | `/architecture` | مرجع للفريق — طبقات الخدمات وملكية كل شاشة |
| التقارير | `/reports` | مؤشرات TRIR/LTIFR · ISO 45001 · خريطة حرارية · مولّد تقارير |

بالإضافة لـ **لوحة الاستعلام** (زر ثابت أسفل كل شاشة) — بتنادي `POST /agent/ask` وبتعرض الأدوات اللي
الوكيل استخدمها مع كل إجابة. قراءة فقط بالتصميم: الوكيل بيجاوب، ومابياخدش إجراءات من رسالة شات.

## 5. بنية المشروع

```
web/src/
  api/
    client.js          محوّلَي axios (الخدمة الأساسية + الوكيل) · JWT interceptor · معالجة 401
    endpoints.js       عقد الـ API — كل نداء في مكان واحد
    mock/
      adapter.js       محوّل axios محلي بيطابق نفس المسارات
      seed.generated.js  مولَّد من ملفات Excel — لا يُعدَّل بالإيد
      data.js          الوصلة: تحوّل أعمدة الأوراق لشكل الشاشات
      live.js          مولّد قراءات الحساسات — random walk مقيّد مش أرقام عشوائية
      agent.js         محاكاة الـ tool-calling بنفس شكل رد FastAPI
  components/
    Icon.jsx           طقم أيقونات مرسوم للمشروع (بديل الإيموچي)
    ui.jsx             الوحدات المشتركة — Card · Kpi · Pill · Table · Timeline · Async
    charts.jsx         تغليف Recharts + مصفوفة المخاطر والخريطة الحرارية والهرم
    layout.jsx         الهيكل · الهيدر · التنقل · الفوتر
    AgentDock.jsx      لوحة الاستعلام
    Modal.jsx
  labels.js            ترجمة الأكواد للعربي
  permissions.js       قواعد الأدوار — مقروءة من مصفوفة RBAC
  hooks.jsx            useApi · usePolling · useAuth · useCan · useToast · useClock
  pages/               صفحة لكل شاشة
```

نقطة تستحق الملاحظة: `useApi` بيرجّع `{data, loading, error, reload}` ومكوّن `<Async>` بيرسم الحالات
التلاتة، فمافيش صفحة بتكرر سلسلة `loading ? … : error ? …`. والمحاكاة بتضيف تأخير عشوائي وبتقدر ترجّع
أخطاء — عشان حالات التحميل والخطأ تكون متجرَّبة فعلاً مش مكتوبة على الورق.

## 6. التصميم

الـ mockup الأصلي كان بلوحة ألوان صناعية (steel navy + أحمر السويدي `#9E1B32`) وخطوط
IBM Plex Sans Arabic / IBM Plex Mono. اتحافظ عليها بالكامل في `tailwind.config.js` و`index.css`.

فرق واحد مقصود عن الـ mockup: **الإيموچي اتشالت** من التنقل وعناوين الكروت واتبدلت بطقم أيقونات
مرسوم (`Icon.jsx`). الإيموچي بيتعرض بشكل مختلف على كل جهاز وبيطلع وحش في نسخة الطباعة اللي بتروح
لملف تدقيق ISO.

كل الأرقام بخط mono مع `tabular-nums` عشان الأعمدة تفضل متعامدة — ده مهم في جدول زي سجل الحوادث.
